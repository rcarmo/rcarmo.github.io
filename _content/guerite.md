## About
Guerite watches labelled Docker containers, pulls updated images and replaces the containers when their schedules allow it. It grew out of the need for a small alternative to Watchtower and can also schedule restarts, health checks and stale-image pruning.

Supporting services are handled before their dependants within a Compose project. Pushover and webhooks report what happened.

## How it works
A Python service talks to the Docker API through a local socket or a remote TLS endpoint. Container labels select schedules and policies. Docker Links and an explicit `guerite.depends_on` label define ordering; Compose's own `depends_on` is not exposed by the Docker API.

A container is skipped when a declared dependency is missing, stopped or unhealthy. Swarm-managed containers are skipped because recreating them as standalone containers could lose service-managed configuration.

## Features
### Scheduled updates
Cron-style labels control image checks, restarts, recreation and health checks per container.

### Dependency ordering
Links and `guerite.depends_on` labels put supporting services first within each Compose project.

### Monitor-only operation
Check for changes without applying updates; per-container labels can override the default policy.

### Notifications
Pushover and JSON webhooks report selected lifecycle events.

### Image pruning
Optionally remove unused images on a separate schedule.

### Docker access
The Docker API grants broad control over the host. A read-only filesystem mount of its socket does not make API operations read-only.
